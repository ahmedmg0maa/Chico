# CHICO NEXUS — Phase 03 | Signature Command Experience

Date: 2026-11-19 · Existing repository: `ahmedmg0maa/Chico` · Target: `chicoteam.vercel.app`.

## Objective

Deliver a recognizable, signature CHICO experience instead of layering generic SaaS cards. Elevate the **existing** production app with deep, restrained optical materials, an authentic command center, navigable operational context, and an immersive login. Preserve full function and real data.

## Delivered implementation

1. **CHICO visual signature**: deepen the physical material system of the actual dashboard with a layered metallic-command frame, sculptural light falloff, engraved grid, refined true-KPI cards, active-period chip, gold action surface and readable podiums. No new names, stats, placeholders or external photos.
2. **Wolf stage**: keep approved calm official wolf and add CSS-only etched cage, volumetric light and perspective grid to its existing, requestAnimationFrame-throttled mouse-responsive theater. No heavyweight WebGL runtime or image replacement.
3. **Authentication portal**: enhance the REAL password screen and its existing signing, session, rate limits, provider and error handling visually; no invented registration, password recovery, auth bypass, DB migration or new credential handling.
4. **Keyboard command palette**: functioning Ctrl/⌘+K search across the actual 13 destinations, plus matching authenticated staff from loaded state. Tap search in existing masthead. Arrow Up/Down, Enter from search input, Escape, Tab focus cycle, mouse selection and overlay close. Activates the existing navigation/profile handler, never duplicates APIs or opens anonymous staff data.
5. **Live KPI presence**: animate actual dashboard value changes only; maintain accessible native text and no fabricated trend semantics. Preserve approved Flags/Tickets/Rating/TIME calculation and Discord poster output.
6. **Navigation polish**: refine current 9-slot dock with active-location metallic detail, preserving approved route order and keyboard Alt+1…8 shortcuts.
7. **Technical footprint**: only existing Motion, CSS, DOM and SVG. `signature-phase3.css` is a source module at the end of the canonical generated CSS compilation. No new third-party runtime, database schema or layout replacement.
8. **Verification**: new `test:signature-stage3` contract appended to prebuild. All old rules, Excel, report, salary, Academy and accessibility/source contracts continue to gate builds.

## Device and accessibility contracts

- Reduced-motion must disable interactive spatial tilt and transitions without restricting navigation, focus and form submission.
- Pointer gestures only on actual fine mouse; touch is fully functional without hover.
- Keep all decorative elements `pointer-events:none`, out of keyboard tab order and unconnected to business data.
- Command palette is a true modal surface with predictable Escape, focus cycling, Enter, clickable results and honest empty state.
- Retain correct Arabic/RTL and the original CHICO TEAM brand text. On 320–390px mobile, ensure tab labels, modal and form remain legible.
- Forced colors keeps visible boundaries and heading text.
- Real-data tests should include empty week, missing Flags baseline, report period scope, ties, archived staff, salary bonuses and academy media.

## QA release gate

- Full CI TypeScript, rules, `npm run build` (all prebuild regression scripts) SUCCESS.
- Preview build READY at the exact head commit.
- Anonymous Preview page routes render signed-out login, not privileged data; review-only route (where applicable) does not touch production.
- Check production healthy database/auth status, exact deployment SHA and aliases after merge.
- Preview DB may be unavailable: that is not proof of authenticated workflow. Do not claim fully authenticated E2E verification if DB reports `DATABASE_NOT_READY`.
- Keep the old production deployment as a rollback candidate. Do not change the database or live staff rows.
