# CHICO Next Generation · 6.0 Preview

**موقع جديد بتقنية Next.js + TypeScript + Supabase PostgreSQL، مصمم للفريق الإداري في OneState / CHICO ME.**

## الحالة الفعلية — مهم
- مشروع مصدر مستقل، وليس تحديثًا منشورًا على `chicoteam.vercel.app`.
- لم تُعدّل قاعدة Supabase أو الإنتاج؛ لا بيانات حقيقية أو كلمات مرور داخل الحزمة.
- لم يمكن تثبيت حزم npm في بيئة إعداد الحزمة لغياب الاتصال بسجل npm؛ لذلك **لم يجرِ تأكيد `next build` أو اختبار المتصفح للتطبيق الكامل**. الاختبارات التي نجحت مذكورة منفصلة.
- استُخدم شعار الذئب والبانر الأصليان من نسخة CHICO التي وفرتها سابقًا.
- قاعدة البيانات الجديدة في مخطط منفصل `chico_next` لمنع الاصطدام ببيانات النسخة السابقة.

## التشغيل محليًا من VS Code

1. فك الضغط وافتح المجلد `CHICO_Next_Generation` في VS Code.
2. شغّل: `npm install`
3. انسخ `.env.example` إلى `.env.local` وأضف القيم السرية محليًا فقط.
4. شغّل `npm run dev` لفتح `http://localhost:3000`.
5. نفّذ ملف `db/001_chico_next.sql` في **قاعدة اختبار Supabase** عبر SQL Editor قبل تسجيل الدخول.
6. اختبر `http://localhost:3000/api/health`، ويجب أن يُرجع JSON عند نجاح الاتصال.
7. ادخل بباسورد CHICO الذي اخترته في `CHICO_OWNER_PASSWORD` (12 حرفًا على الأقل).
8. من «التحكم والإعدادات» اضغط استيراد الأسماء والرتب الرسمية إن كانت القائمة فارغة؛ لا يتم استيراد أي إحصائيات.

## متغيرات البيئة

- `DATABASE_URL`: رابط PostgreSQL عبر Transaction Pooler من Supabase. ليس `sb_publishable` ولا رابط API.
- `CHICO_OWNER_PASSWORD`: كلمة سر موقع CHICO (منفصلة عن كلمة سر قاعدة البيانات).
- `CHICO_SESSION_SECRET`: سر عشوائي لا يقل عن 32 خانة لتوقيع جلسات الدخول. توليده من PowerShell:
  ```powershell
  python -c "import secrets; print(secrets.token_urlsafe(48))"
  ```

**لا ترفع `.env.local` إلى GitHub.**

## الوظائف المتوفرة في الكود

- دخول بكلمة سر فقط، جلسات `HttpOnly` و`SameSite=Strict`، حماية طلبات التعديل بمطابقة المصدر، وحد للمحاولات في قاعدة البيانات.
- لوحة Dashboard بتصميم Premium Gaming عربي/إنجليزي، Dark/Light، قائمة Responsive، حركات Motion مدروسة، مع خيار تقليل الحركة.
- إضافة وتعديل وحذف الإداريين، تاريخ تغيير الرتبة، وحذف بيانات الإداري التابعة مع نسخة احتياطية.
- تسجيل وتعديل وحذف القراءات: Tickets أسبوعية وFlags تراكمية وTIME ساعات عشرية وRating؛ يمنع التراجع غير المبرر للعداد.
- عدم اختلاق القيم: `null` يظل «غير مسجل»، والصفر الحقيقي يظل صفرًا.
- سجل أسبوعي وفتح/إغلاق يدوي، مع حفظ نسخة احتياطية قبل التغيير.
- استيراد XLSX في خطوتين: معاينة أولًا، ثم اعتماد صريح؛ لا تُنشأ أسماء جديدة تلقائيًا.
- حفظ نسخ احتياطية في مخطط `chico_next`، مع إمكانية تنزيلها يدويًا عبر API.
- تقارير PNG مبسطة ببيانات حقيقية فقط لاستخدام Discord.
- `/api/health` يعيد JSON منظمًا لكلتا حالتي النجاح والخطأ.

## القيود قبل اعتماد الإنتاج

- يلزم اختبار عقدة Next.js فعليًا بعد تثبيت الحزم.
- يلزم اختبار SQL الحقيقي مع Supabase Test، بما في ذلك الباسورد والحفظ والتراجع والاستيراد.
- زر استعادة النسخة الاحتياطية مؤجل عمدًا؛ تنزيل النسخة متاح، لكن الاستعادة تحتاج اختبارًا بالبيئة المعزولة قبل إتاحتها من الواجهة.
- تقييمات الأسبوع الحالية متوسط حسابي للقراءات المسجلة وليست متوسطًا موزونًا بعدد Tickets؛ ينبغي اعتماد قاعدة التقييم الرسمية إذا اختلفت.
- يلزم تطوير مقارنة الأسابيع وأذونات إغلاق أسبوع سبق إقفاله مع فحص تداخل فترات القراءات، والتحقق من البيانات المقسمة على مدد متعددة.
- يجب تأكيد أسماء القائمة المستخرجة من النسخة القديمة قبل استيرادها.
- لا تنشر هذه النسخة على نطاق الإنتاج الحالي دون Preview ناجح وموافقة صريحة.

## بنية المشروع

`src/components/CommandCenter.tsx` واجهة التطبيق؛ `src/app/globals.css` نظام التصميم؛ `src/lib/rules.ts` حسابات CHICO؛ `src/app/api/` مسارات الخادم؛ `db/001_chico_next.sql` مخطط منفصل؛ `scripts/test-rules.cjs` اختبارات منطق الحسابات.
