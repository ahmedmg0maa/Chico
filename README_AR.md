# CHICO Studio 4.0 — OneState Web

تطبيق إدارة CHICO GENERAL TEAM بلغة عربية وتخطيط RTL. واجهة واحدة جديدة مستقلة عن CSS/JS القديمة، مع وضع داكن وفاتح وتصميم موبايل.

## الحالة الفعلية
- **تم بناء واختبار نسخة محلية.** لم يتم نشر هذا المشروع على حساب المستخدم في Vercel أو ربطه بقاعدة Supabase حقيقية حتى الآن.
- قاعدة البيانات **الجديدة** تبدأ بأسماء الإداريين والرتب الموجودة في مصدر التطبيق فقط، **من دون أي Tickets أو Flags أو Rating أو TIME أو تقارير أو لقطات أسبوعية**. بيانات الاختبارات لا تدخل المنتج.
- إذا تم توصيل قاعدة Supabase فيها معلومات قديمة، لن نمسحها تلقائيًا. استخدم «الإعدادات ← مسح الإحصائيات فقط» لتصفير الأرقام والإبقاء على الأسماء والرتب.

## كيفية الدخول
**كلمة مرور واحدة فقط** من غير Username أو اسم مستخدم أو حسابات لأفراد الفريق. كل من يعرف كلمة المرور يمتلك صلاحيات إدارة كاملة؛ لا تشاركها مع غير المصرح لهم.

## إدارة الفريق
- إضافة، تغيير الاسم، الرتبة (Responsible / Administrator / Moderator / SN.Helper / Helper)، حالة النشاط، الظهور في التقارير، ترتيب القائمة.
- حذف إداري أو حذف مجموعة محددة من الإداريين، مع حذف السجلات التابعة لهم؛ إجراء الحذف يحتاج كتابة DELETE ويُنشئ نسخة احتياطية أولًا.
- حذف أي قراءة/Rating/مناوبة/Opening Flags/تقرير محفوظ من الأسبوع المفتوح، مع إعادة حساب Flags وTickets والتأكد من عدم وجود تضارب. تعديل الأسبوع المغلق مباشرةً مقيد لحماية التقارير التاريخية؛ «مسح الإحصائيات» متاح لإعادة البداية كليًا.
- «مسح الإحصائيات فقط»: يحذف الإحصائيات والتقييمات والقراءات والتقارير والأرشيف ويترك الأسماء والرتب.
- «حذف كل بيانات الفريق»: يحذف أيضًا الأسماء والرتب، ولا تُعاد قائمة الأسماء تلقائيًا عند فتح الموقع مرة أخرى.
- النسخ الاحتياطية تُحفَظ قبل الحذف تلقائيًا ويمكن استعادتها. لو تريد إتلافها نهائيًا، يوجد زر مستقل **«حذف كل النسخ الاحتياطية»** مع تأكيد إضافي بكلمة المرور. النسخ التي تحتفظ بها أنت خارج الموقع أو شركة الاستضافة ليست ضمن المسح.

## تسجيل بيانات اللعبة
- استيراد XLSX بمعاينة واضحة ومطابقة أسماء قبل الاعتماد؛ لا حذف أو إضافة صامتة.
- تسجيل يدوي بمدخلين لـ Tickets: عدد أسبوعي من اللعبة (counter) أو زيادة فترة (direct)، مع تواريخ التغطية (أي عدة أيام لا تُقسَّم تلقائيًا).
- TIME ساعات عشرية: 1.5 تعني ساعة ونصف. Flags تراكمية وتُستخرج فروق الأسبوع من رصيد البداية والمقارنة.
- ترتيب Top 3 للـ Moderators والـ Helpers، مع استبعاد Responsible من الحسابات غير المقصودة.
- إغلاق أسبوعي يدوي مع مقارنة تقرير القائد؛ الأرقام غير المكتملة لا تُعرض على أنها نتائج مؤكدة.

## نشر Vercel + Supabase
1. أنشئ مشروع Supabase ثم انسخ **Postgres transaction pooler URI** الآمن؛ لا تستخدم مفتاح anon أو Service Role في موقع الواجهة.
2. أنشئ مستودع GitHub خاصًا واحمل محتويات المجلد الجذر إليه، ثم أنشئ مشروع Vercel من المستودع.
3. ضَع متغيرين **في إعدادات Environment Variables بالخادم**: `DATABASE_URL` و`CHICO_OWNER_PASSWORD` (كلمة مرور قوية 12 حرفًا على الأقل). لا تضع الأسرار في ملفات المشروع العامة.
4. راجع أن Vercel يوجّه API من `api/index.py` وأن ملفات `public/` تعمل، ثم انشر نسخة Preview أولًا.
5. جرّب `/api/health` ومجرى Login → إداري → قراءة Excel → تقرير → نسخة احتياطية → إعادة تعيين، ثم لا تفعّل إنتاجًا قبل اكتمال التحقق من Supabase الفعلية.
6. `CHICO_OWNER_PASSWORD` يُستخدم للتهيئة الأولية فقط عند إنشاء قاعدة بيانات جديدة. تغيير كلمة السر من إعدادات الموقع يحفظ كلمة جديدة مجزأة في قاعدة البيانات؛ تأكد من توثيقها في مدير كلمات المرور.
7. احفظ `DATABASE_URL` ومعلومات الدخول في إعدادات Vercel/Supabase، ولا ترسلها في المحادثة أو ترفعها إلى GitHub.

## التشغيل المحلي للاختبار (Windows/macOS/Linux)
- Python 3.11+، ثم `pip install -r requirements.txt`.
- Linux/macOS: `CHICO_LOCAL_SQLITE=1 CHICO_LOCAL_DATA=./local_data uvicorn api.index:app --reload --port 8000`
- Windows PowerShell: `$env:CHICO_LOCAL_SQLITE='1'; $env:CHICO_LOCAL_DATA='./local_data'; uvicorn api.index:app --reload --port 8000`
- افتح `http://127.0.0.1:8000`. كلمة مرور وضع التجربة المحلي فقط `ChicoAdmin`؛ **غير صالحة كنظام دخول إنتاجي**.
- لا تشغل `CHICO_LOCAL_SQLITE` على Vercel؛ البيانات الدائمة هناك تحتاج Supabase.

## جودة التنفيذ
تم اختبار منطق الحسابات ومسارات API المحلية، وتجربة الدخول وتعديل وحذف الإداريين من خلال متصفح محلي وسيط (لا رابط منشور). **لم تُختبر الكتابة إلى PostgreSQL على Supabase الحية** ولا الاستعادة السحابية في حساب المستخدم.
